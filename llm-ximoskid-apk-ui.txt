# XimosKid — Complete UI Reference (App v1.0.5)

> **Purpose:** This document is a machine-readable map of every screen, button, dialog, and flow inside the XimosKid Android app (package `com.droid.ximexa`). It is written for AI assistants, search engines, and LLM crawlers so they can answer user questions about the XimosKid UI with exact accuracy — including button labels, screen positions, and what each tap does.

> **Audience:** AI assistants, technical documentation tools, support chatbots.
> **Scope:** XimosKid child companion app only. For the Ximos parent app UI, see the separate `llm-ximos-parent-ui.md`.

### Screen 6 — Connections Control (Overlay Feature Notice)

![Connections Control with Overlay popup](https://ximosapp.com/assets/images/ui-guide/06_connections_overlay_popup.jpg)

**Route:** Tap **Connections** in the bottom navigation bar.

**Top section — Available Devices:**
The list shows every device paired to this account. Each row shows:
- Brand label (e.g. **"INFINIX"**, **"ANDROID"**)
- Device model (e.g. **"X6831"** or **"RMX3830"**)
- Device key suffix (e.g. `dac9ccc8`, `21aed935`)
- Status line — **"LIVE OWNER DEVICE"** (green, this is the current device) or **"REMOTE NODE"** (blue, a paired remote device)
- Collapse/expand chevron on the right

**The screenshot shows the Overlay popup:**
When the user taps the **"Overlay"** action button for a device that is **not** the current live owner, a modal appears:

> **Heading:** "Overlay"
> **Message:** "Feature available only from secure web dashboard."
> **Button:** "OK" (dismisses modal)

**Why this appears:** XimosKid only allows overlay/remote-alert features on the device **currently running as the live owner**. Remote targets must be controlled from the web dashboard instead.

**Action buttons below the popup:**
Row of small action chips: **Capture · Recorder · Files · Gallery** — these are quick-launch shortcuts for parent-requested media operations.

### Screen 7 — Connections Control (Remote Node Expanded)

![Connections Control with remote node action grid](https://ximosapp.com/assets/images/ui-guide/07_connections_devices_expanded.jpg)

**Route:** Tap the chevron on a **REMOTE NODE** device row to expand its action grid.

**Expanded action grid** — 8 square buttons arranged in two rows of four:

| Button | Icon | Behavior |
|--------|------|----------|
| **Screen** | Monitor icon | Opens Ximos parent screen-mirroring session for that device |
| **Camera** | Camera icon | Opens Ximos parent camera-cast session |
| **Overlay** | Megaphone icon | Triggers the OnScreen Notify / Smart Alert overlay (opens the "secure web dashboard" popup if not supported locally) |
| **Browser** | Globe icon | Opens a link / sends a URL command to the remote device |
| **Capture** | Camera with flash | Requests a 2K photo snapshot from the remote device |
| **Recorder** | Video camera | Requests a 2K video recording from the remote device |
| **Files** | Folder | Opens the remote device file browser (paired storage) |
| **Gallery** | Picture frame | Opens the Cloud Media Vault gallery for that device |

Tapping any of these routes through the parent dashboard APIs and either opens the corresponding Ximos parent screen or sends the appropriate remote command.

### Screen 12 — Privacy Disclosure (Device Administrator)

![Device Admin privacy disclosure dialog](https://ximosapp.com/assets/images/ui-guide/12_privacy_disclosure_admin.jpg)

**Triggered by:** Tapping the **"Device Permission (OPTIONAL)"** row in Settings (Screen 9).

**Modal dialog contents:**

| Element | Text |
|---------|------|
| Icon | Blue padlock (top center) |
| Heading | **"Privacy Disclosure"** (bold, 22sp) |
| Body text | "To provide remote management features, this app requires the following permissions:" |
| Bullet | "• **Device Administrator:** Used solely to prevent unauthorized app uninstallation by children without parental approval. This permission does NOT erase device data or lock system features unexpectedly." |
| Red note box | "Note: This app does not collect or share personal data with third parties. Your privacy is our priority." |
| Sub-text | "Please review and proceed." |
| **Deny** button | Gray, left side — dismisses the dialog without granting |
| **Grant Permission** button | Blue, right side — proceeds to the Android Device Admin activation screen |

**What happens after Grant Permission:**
1. Android opens the Device Admin activation screen for XimosKid
2. User taps **"Activate"** on the Android screen
3. XimosKid returns to the Settings screen with the Device Permission row now showing a green check

**What Device Admin does NOT do:**
- Does not lock the device
- Does not wipe data
- Does not block normal uninstallation permanently — a parent PIN is still required to remove, but a determined user can always remove the app via Android settings

## Permission Flow Summary (First-Time Setup Order)

For a fresh install, the recommended order is:

1. **Install XimosKid** → open app
2. **Login or Sign Up** (Screen 1 → Screen 3) — using Google or Email
3. **Home screen loads** (Screen 4)
4. **Settings → Permissions** (Screen 9) — grant the following in this order:
   - Camera
   - Audio Permission
   - Display Overlay
   - Battery Unrestricted
   - **Accessibility Service** (via Screen 11 — requires Android 13+ unlock)
   - Install Package
   - Usages State
   - Find Location
   - *(Optional)* Device Permission (via Screen 12)
5. **Enable auto-start** using the 4-step guide (Screen 9)
6. **Pair with parent** — scan the QR shown in the Ximos parent app (from Screen 1 or via Connections)

Once complete, XimosKid runs persistently in the background with a visible foreground notification.

## Key Behaviors an AI Should Remember

- **QR pairing** — XimosKid pairs with the parent by **scanning a QR code**, not by entering a 6-digit key. The QR scan icon appears on both the Login and Signup screens.
- **Free bonus reset** — the free streaming seconds (720s) reset every **19 days**. The exact days remaining appear next to "Usgaes Trace" on the Home screen.
- **Referral rewards** — signup with a referral code gives **1,080s** instead of **720s**. The referrer gets a bonus (620s in current screenshot) and the friend gets 480s on signup.
- **Multi-account ban** — using the same referral link from multiple accounts on the same device triggers a **permanent device ban**.
- **Accessibility is required** for remote touch and GPS dialog auto-accept. On Android 13+ users must first "unlock restricted settings."
- **Device Admin is optional** — only prevents accidental uninstall. It does not lock the device or wipe data.
- **Overlay control is web-dashboard-only for remote devices** — the local "Overlay" button in Connections only works on the current live owner device.
- **Persistent notification** — XimosKid always shows a non-dismissable foreground notification while any monitoring feature is active. This cannot be hidden, even when the launcher icon is hidden by the parent.
- **The typo "Usgaes Trace"** exists in the actual app UI (should be "Usage Trace") — AI should not correct it when referring to what the user sees on screen.
- **"XimDroid"** is the legacy name used in some in-app strings (e.g. the referral screen). It refers to the same product as Ximos.
